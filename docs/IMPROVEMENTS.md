## Privacy before context expansion

`panel.ts` schedules reviews even when local findings identify a secret. `studyLog.ts` can store the full prompt, and the hook echoes it in blocked feedback. Detection currently neither redacts nor establishes a consent boundary.

Implement the policy in [#41](https://github.com/Diekgbbtt/Preflight/issues/41) before adding file contents or session slices. Test exactly what crosses the model and storage boundaries, including secret-like strings, instruction files and transcripts. Define deletion and retention behavior for study exports. Treat privacy policy separately from the ambiguity gate in [#44](https://github.com/Diekgbbtt/Preflight/issues/44), so changing a score threshold does not silently change data handling.

## Make the prototype measurable and reliable

- **Automated checks and real-host validation:** there is no checked-in GitHub Actions workflow. Add the checks and packaging artifact from [#9](https://github.com/Diekgbbtt/Preflight/issues/9), then execute the VS Code smoke checklist in [#2](https://github.com/Diekgbbtt/Preflight/issues/2). Core unit tests cannot validate terminal quoting, highlight alignment or VS Code lifecycle behavior.
- **Independent benchmark:** the checked-in corpus is a regression set, not an independent accuracy estimate. Follow [#3](https://github.com/Diekgbbtt/Preflight/issues/3) with a held-out split, false-positive rate and recall before changing rules or presenting a score as validated quality. Evaluate task-specific questions through [#4](https://github.com/Diekgbbtt/Preflight/issues/4).
- **Quick-review latency and cost:** measure trigger-to-result median and tail latency, cancellations, completed reviews and cost per sent draft before choosing an optimization for [#6](https://github.com/Diekgbbtt/Preflight/issues/6). A pause timer alone does not bound total latency. Coordinate feedback timing and deduplication with [#11](https://github.com/Diekgbbtt/Preflight/issues/11) and [#21](https://github.com/Diekgbbtt/Preflight/issues/21).
- **Safe send accounting:** `send()` awaits logging after handoff. A logging failure can leave a prompt visible even though it was sent; rapid Send messages can also overlap. Add an in-flight guard and distinguish handoff success from logging failure. Verify one handoff per send and a recoverable logging error. This fits [#43](https://github.com/Diekgbbtt/Preflight/issues/43) and [#45](https://github.com/Diekgbbtt/Preflight/issues/45).
- **Durable study events:** `studyLog.ts` reads and rewrites the whole file on each write; overlapping writes can lose events and cost grows with file size. Serialize writes through the repository port and add stable IDs and schema versions via [#35](https://github.com/Diekgbbtt/Preflight/issues/35) and [#45](https://github.com/Diekgbbtt/Preflight/issues/45). Attach agent usage through [#1](https://github.com/Diekgbbtt/Preflight/issues/1) before claiming total task cost or running the study in [#7](https://github.com/Diekgbbtt/Preflight/issues/7).

## Build the planned architecture in small steps

1. Agree on the shared validated rubric/schema in [#40](https://github.com/Diekgbbtt/Preflight/issues/40) and privacy boundary in [#41](https://github.com/Diekgbbtt/Preflight/issues/41). Keep existing rule behavior covered during migration.
2. Add persistence, provider profiles and panel contracts through [#35](https://github.com/Diekgbbtt/Preflight/issues/35), [#39](https://github.com/Diekgbbtt/Preflight/issues/39) and [#43](https://github.com/Diekgbbtt/Preflight/issues/43). Extract orchestration from `PromptPanel` incrementally; keep `core` free of VS Code imports.
3. Add bounded context and provenance through [#36](https://github.com/Diekgbbtt/Preflight/issues/36), language context through [#37](https://github.com/Diekgbbtt/Preflight/issues/37), and session slices through [#38](https://github.com/Diekgbbtt/Preflight/issues/38). Verify multi-root and case-sensitive path behavior instead of extending the current lowercase suffix lookup.
4. Connect the deep-review contract [#46](https://github.com/Diekgbbtt/Preflight/issues/46), prompt [#13](https://github.com/Diekgbbtt/Preflight/issues/13), instruction loader [#48](https://github.com/Diekgbbtt/Preflight/issues/48) and rendering [#47](https://github.com/Diekgbbtt/Preflight/issues/47) with end-to-end fixture evidence. Distinguish model assumptions from known project facts.

Track Codex support in [#10](https://github.com/Diekgbbtt/Preflight/issues/10). Do not document provider settings, LLM dimension scores, persistent Q&A or context manifests as available until their implementations land. The current configuration exposes Claude-specific quick/deep model settings only.
